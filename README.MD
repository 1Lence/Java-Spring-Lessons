Тема УБЕР тяжелая, явно не что бы за неделю её почитать посмотреть, ушло очень много времени на ошибки при запуске
сервера кафки и ещё больше времени на ошибку десериализации. Зато много информации впитал, пока искал решения проблем.

Создал "Производителя" в этом проекте и "Потребителя". Ничего особенного, простой обмен джсоном как в требованиях
(Очень хотелось ещё логики реализовать, но времени не хватило и не хватит)

1. id – имя этого листенера
2. topics / topicPattern - Говорит, от каких топиков слушать сообщения
3. groupId - Название группы потребителей, слушателей
4. containerFactory - Название бина, который настраивает как читать сообщения, если не указать, то он возьмет дефолтное
5. autoStartup - Автоматически стартовать листенер при запуске приложения
6. concurrency - Сколько потоков будет обрабатывать сообщения
7. errorHandler - Можно указать свой обработчик ошибок
8. clientIdPrefix – префикс к ID клиента в Кафке(что-то для отладки, не особо понял)
9. topicPartitions – можно настроить какие конкретно партиции будет слушать, для кластерной системы
10. properties - можно указать доп параметры
11. splitIterables – разделение сообщений если их много
12. beanRef - ссылка на бин листенера
13. idIsGroup - из Id делает groupId 
14. batch - получение пачками сообщений 
15. filter - фильтрация сообщений 
16. contentTypeConverter - можно указать бин своего десериализатора
17. containerPostProcessor - доп настройки перед стартом приложения
18. info - как комментарий, просто описать листенер
19. containerGroup - группировка контейнеров слушателей
